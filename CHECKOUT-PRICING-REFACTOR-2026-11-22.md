# Checkout pricing and loyalty extraction

Draft updated to production `ce80ccc0c2117f1988ad60e9a10947f68a8e1861`, including both the corrected delivery fallback message and the separately published quote-refresh fix (PR #104).

`customer-checkout-pricing.js` registers a classic-script factory containing twelve existing functions (523 lines): voucher validation/revalidation, loyalty application/projection/rendering/lookup, delivery hint helpers and total recomputation. Bootstrap keeps shared state, phone lookup generations and event listeners; public function names remain compatibility wrappers. Initialisation occurs after loyalty state is created, before existing recomputation listeners are registered. Mutable subtotal, voucher and loyalty state are read through live getters; writable scalar state has setters. Function dependencies are called unbound, preserving the original invocation behavior. Loading the factory performs no DOM, storage or provider operations.

No changes to calculation order, rounding, fee thresholds, loyalty eligibility/reservations, provider endpoints, UI wording, scheduling, checkout payloads or backend authority. No new framework or asynchronous loader. Script order and cache keys updated; browser test asset serving includes the module.

Combined validation: 141 tests pass. The extraction record stores the exact prior function bodies and verifies that the only edits inside them are explicit dependency accesses. Replacing wrappers and removing the recorded initializer reconstructs the complete production bootstrap byte for byte, including mixed line endings. Historical earlier extraction proofs compose through this reconstruction; dedicated pricing and loyalty tests execute the current factory.

Actual current pricing output is compared to the released functions across 540 combinations of subtotal, voucher, reserved/available loyalty balance and collection/delivery quote state, including zero distance, unknown distance, route fallback, loading and explicit ineligibility. Additional tests exercise live state changes, voucher refresh/removal and loyalty transport success/failure without provider traffic. The corrected fallback wording has executable coverage against the extracted message block.

Hosted preview `23a4c4ff` built successfully. Browser check: £2 rice basket showed Collection total £2 and two pending food points; Delivery to the restaurant's public address used the £3 route-price fallback, showed the corrected fallback wording and total £5, and still earned two points. No customer identity, date or order submission was used.

Release blocker found during threshold check: close checkout, increase the basket from £2 to £30, then reopen with Delivery retained. The free-delivery text appeared but the existing quote's £3 fee remained, giving total £33. Switching Collection then Delivery refreshed the quote and produced fee £0, total £30 and 30 pending points. This is consistent with unchanged dialog opening behavior, which updates the subtotal and recomputes totals without requesting a fresh delivery quote. The recorded byte-preserving extraction and baseline comparisons do not certify the correctness of that existing quote lifecycle. Track the refresh fix separately rather than silently altering pricing behavior in this extraction.

No application console errors were observed during these checks. No order or basket review was submitted.
